# Repository Changelog

## Unreleased

### Changed

- **800-image `rvl_cdip_800` evaluation (new env)** — qwen3.7-flash on 800 images (50/class × 16): **v0 529/800 (66.1%)**, **v11.8 665/800 (83.1%)**. v11.8 gains +17.0pp over the v0 baseline on the same 800-image slice. v0 cost $0.1792 expected / $0.1773 actual (+1.1%); v11.8 $0.3276 expected / $0.3427 actual (+4.6%, heavy prompt caching — ~61% of prompt tokens cached at 10%). v11.8 top confused pairs: budget→invoice (13), letter→memo (10), invoice→budget (7). Reports + confusion matrices in `reports/` (`experiment_reports/`, `confusion_matrices/`, `failed_reasoning_traces/`).
- **v0 baseline prompt evaluation** — added `PROMPT_V0` (915-char function-not-subject-matter baseline, no check structure) and ran it on the 480-image `fixed_size_sampled_480` slice with qwen3.7-flash: **69.2%** (332/480) exact_match, 0 failed rows, expected cost $0.085 vs actual $0.0846 (+0.5%). Strongest classes: memo 100%, advertisement/email/scientific_publication 93%. Weakest: presentation 37%, budget 43%. Provides a control point for measuring prompt-engineering gains over the v17.x line.
- **New Braintrust environment migration** — project moved to `AMFAMv2` (org `4cb7718c-...`, project_id `9e76bd46-...`). `copy_datasets_to_new_env.py` re-uploads dataset slices with sync attachment upload + 8 retries (S3 PUTs are intermittently flaky). `.env` still carries the old key; scripts must use `config.api_key` from `load_braintrust_config()` (new key).
- **v17.2 three-slice generalization** — two new counter-example worked examples (invoice with form layout → invoice, newspaper page with embedded ad → news_article) and two calibration sentences (form-is-never-a-default, presentation vs memo slide-style). The 4 redundant v11.9 worked examples (questionnaire, scientific_report, scientific_publication, estimate-change-order) were stripped from the v17 base — they redundantly teach rules already explicit in the check structure and contributed to v16's 81.6 % accuracy. Sourced from v17.1 v1+v2+v3 multi-slice analysis (53 failures across 480 images, ~89 %). Four counter-examples total, all teaching overrides the raw check structure doesn't encode. 46,870 chars (+2,216 vs v17.1; -4,883 vs v16, -9.4 %). v17.2 is now the default prompt.
- **v17.1 surgical enhancements** — two worked examples (handwritten letter → handwritten, agency estimate → budget) and two calibration sentences added. Sourced from v16 v2+v3 analysis (81.6 %). v16's worked examples actively taught the wrong behavior; the replacements reverse that guidance.
- **Truncated-response salvage** — the eval retry loop now calls `extract_prediction()` on every response BEFORE checking `finish_reason`. Truncated (`finish_reason=length`) and provider-errored (`finish_reason=error`) responses often still contain a valid classification label; this rescue recovers the ~10 % of samples that were previously discarded as evaluation failures after exhausting all retries.
- **`finish_reason` logged in Braintrust metadata** — every successful row now records its API `finish_reason` in the span metadata so salvaged predictions can be identified and audited.
- **v17 prompt now default** — replaces v16 with a streamlined v11.9 derivative that removes the agency-estimate sub-protocol from check-7 (budget/invoice) and adds an explicit LETTER/MEMO OVERRIDE in check-2 (handwritten). Prompt is 4,627 chars lighter than v16 (46,277 vs 51,753), eliminating the finish_reason=length failures caused by qwen3.7-flash exhausting reasoning tokens on the bloated v11.9 check-7 section.
- **Reasoning effort reduced to `medium`** for qwen models (was `high`) to further cut token burn and eliminate `finish_reason=length` failures; 13 of 16 failed rows in v16 multispect were length-related.
- **MAX_TOKENS_CAP raised to 32,768** (was 16,384) as an additional safeguard against reasoning-token exhaustion.
- **Failed-row tracking** — errored rows now return an `ERROR:` sentinel output and are scored as both `exact_match` (miss) and a new tracked `failed` metric in Braintrust experiments.
- **HTTP timeout (300s)** added to the OpenAI client to prevent hung eval runs on stalled provider connections.
- **Manifest support** added to all eval launches for resumability after interruptions.

### Added

- `src/notify.py` — local completion sounds (macOS): a Mario-style rising C-major power-up jingle for success and a descending game-over motif for failures, synthesized with numpy and played via `afplay` (no audio assets or external packages). `play_success()` and `play_failure()` are safe to call anywhere and never raise.
- `resume_until_complete.py` — re-invokes the eval runner from its manifest checkpoint until every dataset row has a final status, so a run persists to full completion even if the Braintrust side crashes or caps out. Alerts with the failure motif on eval-process crashes and on abandonment after `--max-cycles`.
- `score_manifest.py` — computes final numbers (exact_match, per-class accuracy, error/empty counts) directly from the local manifest JSONL with **no Braintrust calls**, saving `_final.json` + `_final.md` into `reports/experiment_reports/`. Guarantees result numbers are always available even if Braintrust score/credit limits cap out.
- `run_v11_8_800_after_480.py` — eval queue script that waits for an in-flight 480-image run to complete, then runs the v11.8 prompt with qwen3.7-flash (high reasoning, 8192 max_tokens) on the 800-image `rvl_cdip_800` dataset using the `RESEARCH_FUNDING_API_KEY` OpenRouter key.
- Classification prompt `v16` (v11.9 + 2 worked examples for budget↔invoice and handwritten↔letter). Deprecated in favor of v17.
- `v16_multislice_evaluation_report.md` in `reports/` — full three-slice analysis identifying the three root causes of the drop from ~99% to ~80% exact_match.
- `eval_160_v16_v1.log`, `eval_160_v2_v16.log`, `eval_160_v3_v16.log` — raw v16 evaluation logs.
- `eval_v16_v{1,2,3}.jsonl` manifests in `reports/manifests/` for all v16 runs.

### Changed

- **Resilient eval retry loop** — `braintrust_openrouter_input.py` now: (1) fails over to the alternate OpenRouter key (`RESEARCH_FUNDING_API_KEY`) when the primary hits a quota/credit 403, (2) throttles adaptively on upstream 429s (records recent rate-limits, sleeps per `Retry-After` or an escalating 5/15/45s backoff), (3) sleeps 2s/4s for other transient errors, (4) salvages rows that fail all primary retries with one attempt through `--fallback-model` (e.g. `google/gemini-2.5-flash-lite`) — designed for content-filtered images, and (5) logs span metadata safely (never raises on Braintrust logging failure). Per-error-type backoffs are module-level constants.
- **`--fallback-model` wired through `resume_until_complete.py`** — the resume watcher passes the salvage model through to each relaunched eval cycle, and `--no-score` disables its new default auto-scoring of the manifest on completion (via `score_manifest.py`, zero Braintrust credits).
- **Completion alert sounds** — the eval runner (`braintrust_openrouter_input.py`) now plays the success jingle at the end of a run with zero failed rows and the failure motif if any row errored (catchall for failures/errors in a Braintrust run). Mute with `--no-sound`.
